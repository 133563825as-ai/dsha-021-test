# R2-B06 · DocumentsProvider 父路径替换（隔离复现中）

2026-09-28。限定 `DshaDocumentsProvider.createDocument`、`renameDocument`、`deleteDocument` 与其 `DocumentPaths` 解析边界；只用 `app/build/round2-audit/b06/` 下可丢弃合成目录，不触碰正式设备/用户 `.dsh`。这是一项**未定性风险**，不先按理论更改产品代码。修复前封存依据见 `agent-b-audit.md` 的待复现段落。

现有调用链：`DocumentPaths.resolve()` 逐组件读 guest/宿主链接并返回 `File`，Provider 的 `resolve()` 再检查私有保护目录。创建在 `existing(parent)` 与子项 `resolve(id,false)` 后调用路径式 `mkdir/createNewFile`；改名在 source/target 解析、冲突检查与 descendants 枚举后调用 `File.renameTo`；删除先枚举 descendants，再逐项重新解析并调用 `File.delete`。Provider 的 `synchronized` 只串行化本 Provider 实例，不能阻止同 UID guest 写者在解析与最终 syscall 间换父目录。`openDocument` 另有 fd 真实位置检查且在核验后才 `ftruncate`，必须单独判断，不能把创建/改名/删除的推论套给读写 fd。

复现标准：在隔离根外放内容固定的哨兵目录；让解析阶段看到根内合法父目录，随后用受控闩锁把该父路径替换为指向外部哨兵的链接，再执行与生产一致的文件操作。分别记录创建是否在外部生成新文件、改名是否搬走外部文件、删除是否删到外部对象；逐案核对原件/链接/inode 与失败返回，不能只看路径字符串。再验证链接本身删除仍仅删链接、旧 `root`/`linux/ubuntu/...` 文档 ID 不变、guest 绝对链接在根内仍可用，以及既有 `openDocument` fd 检查不会在核验前截断错误对象。若真实操作未越界，如实排除或收窄风险；若有越界，再按最小目录 fd 相对操作/身份约束修补并测试取消、锁寿命和授权的逻辑子路径与实际目标双判据。
