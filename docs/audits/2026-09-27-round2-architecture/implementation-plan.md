基于已封存台账进行如下工作包；接口和验收可在有证据时细化，新增问题先追加 fixes.md。用户已授权按依赖推进，无需等待再次确认。

1. 主代理：修复屏幕确认统一后置核验 R2-B03；负责 HttpShellService/ScreenSessionGrant 与对应测试。保持敏感动作逐次确认和原通道策略。主代理还负责评分、单源构建输入、验收契约、所有 Gradle/手机/交付操作。
2. A组：维护权威与 Controller owner (R2-A01/A03)，迁移生产调用方，保持快照/独占/嵌套和未知退出不释放；修 R2-D01 资源所有权。先交付该纵切面再处理 A04，不一次改写所有执行器。写入 core/runtime/BackupManager 及明确调用点，先与B组协调 backup调用点。
3. B组：R2-B01 插件卸载持久事务及隔离中断恢复，写 plugin-manager/plugin-transactions/PluginInstallJournals 与测试；接着处理 R2-B02 历史活动分离，确保旧 completed 并非无条件信任。共同领域代码修改需单一负责人，避免A组同改 NativeBackupJobs。
4. C组：R2-C01/C04 浏览器兼容与上传所有权。正式/应急及两内核保留来源隔离；不能将加载后补丁当作前置兼容。写 UI/Low UI/新纯上传策略及对应测试。构建与验收脚本由主代理负责。
5. 再处理 R2-A04 命令/部署职责：据首批接口确定窄边界，补行为测试，迁移真实调用者。A02与Provider竞态等风险仅在隔离复现后进入修复；无法读取身份继续 fail-closed。
