## 裁决原则

技术债只计**当前调用链可证、能说明用户后果的可避免成本或重复权威**。正式个人数据不做破坏性故障注入、旧用户归档没有逐份验收、某厂商设备缺席，是验收边界，不能当成实现失败来抬分。旧 v1/修改过/含额外文件的日志保留在 active、重复 ID 禁止模糊写入、独立应急根和两种运行方式是保护约束，不因“目录多”判为待删债。目标低于 20 不构成放松上述约束的理由。

| 裁决 | 当前证据、用户后果与安全下一步 |
|---|---|
| **原范围内必须继续做隔离复现：DocumentsProvider 父路径替换** | `DocumentPaths.resolve()` 在组件检查后返回 `File`；`DshaDocumentsProvider.createDocument/renameDocument/deleteDocument` 随后用路径名再次调用 `mkdir/createNewFile/renameTo/delete`。Provider 自身的 `synchronized` 不能阻止同 UID guest 或其它文件写入者替换父目录。`openDocument` 已有 fd 位置核验，不能混同为这三项都安全或都越界。现在**没有并发越界动态证据**，故不登记已证实安全缺陷；但隔离复现是可执行工作，不能称外部阻塞。下一小包在非正式、可丢弃的临时树，用受控闩锁在“解析后、实际 syscall 前”替换父目录，分别测试创建、改名、删除和链接本身删除；外部哨兵必须保持原字节，记录实际路径/inode 与返回结果。先用支持软链接的宿主/CI 文件系统与生产 `DocumentPaths` 逻辑复现，再在允许的隔离 Android 环境核 Provider 行为；不得在正式 `.dsh`/用户文件上注入。若可复现越界，才把风险升为缺陷，并以目录 fd 相对操作或等价的核验后使用边界修复，保留旧 document ID 与 guest 绝对链接语义。 |
| **可小范围验证，但需先裁决撤销语义：ADB SMS 在途计划** | `HttpShellService.devicePlan()` 取得计划时检查 SMS 预授权；`adb-shell.py` 拿到计划后还要读密钥、建连并发送。关闭预授权发生在两步之间时，旧计划的发送前没有第二次原生核对。当前未知产品的“关闭立即阻止新查询”是否涵盖**已获计划、尚未发往设备**的请求，不能直接写成已越权。可用隔离桥夹具在 plan 返回后暂停连接、撤销授权，再观察是否发生真正 `content query` 发送；只记录命令类型与时序，不读取短信正文。若要求撤销阻止未发送查询，采用一次性、代次绑定的发送前确认票据，不在结果未知后重放。Root 执行前另查授权，Shizuku 本来不走敏感 SMS，此项限 ADB。 |
| **可小范围验证，暂不定缺陷：虚拟屏异步撤销** | `HttpShellService.revokeScreenGrant()` 同步递增 UI grant revision，但 `VirtualScreenManager.revoke()` 将实际 token/会话停止排入 worker。新桥请求受同步 grant 挡住；已进入 native manager 或队列中的动作是否越过撤销时点尚无隔离时序。用可控 worker/连接闩锁分别测启动中撤销、已排队 touch、Root/Shizuku/ADB 通道与 generation 变化，只记录是否有**撤销后新动作**。已有在途动作不能倒退撤销；不以“异步排队”本身判失效。 |
| **条件性救援能力，不为分数直接实施：重复物理原件的单份导出** | B05 让 active/completed 同 ID 两份各显示物理位置，并拒绝按模糊 logical key 的勾选、导出和恢复。这防止误用，但若用户确有唯一旧源码只在冲突目录，当前 UI 不能从该行执行只读导出。先确认实际用户救援需求和最小范围；若要实现，应只导出用户明确选择的物理目录并绑定本次 inode/摘要，**不**把它作为可启用或自动恢复候选。没有真实重复原件求助，不把当前 fail-closed 判据报成已造成数据丢失。 |
| **有代码成本，先测量再优化：显式历史深页** | R2-B02 已使普通启动门禁不再遍历经证明的完成历史；R2-B05 的单页候选堆 O(pageSize)，但为真实总数和游标指纹，显式 `RetainedCatalogue.page()` 每页仍读完整目录名字，峰值含最大单根 `fs.list()` 结果。宿主 1,000 条批量查找从逐 10 次约 170,170 降到一次约 17,017 次 FS 调用；当前最终 Low 普通 UI 只有 11 条且只读检查/旋转通过，**没有已测的深页卡顿**。用可丢弃合成历史测 1,000/5,000 条首页、深页的非调试设备延迟和 PSS/FD 前后趋势，超出可接受阈值才设计仅供展示的会话索引；导出/恢复仍查真实源。不为分数扩写全文件系统 API 或截断历史。 |
| **需便携范围决定，不可直接排除：插件日志进入 v5** | `NativeDataLocations` 可把 `.dsh/plugin-install-operations` 作为 `dsh-child` 打进用户归档；`NativeRestoreTargets` 导入时隔离到 `plugin-imports`，外来 `.completed-proof-v1.json` 不会变成活动事务授权。它可能增加归档字节，但日志也可能保存旧插件源码的唯一副本。先量其实际体积，并明确便携归档与显式历史导出的范围，再决定是否调整来源；**不**把整棵插件历史当缓存删掉。当前没有直接授权绕过证据。 |

## 哪些不应继续推断为缺陷

- `HostMaintenancePending` 已把七个可恢复域合为同一只读 probe 序列；普通取首项、恢复最多数到两项，`bounded-guest` 继续由进程围栏处理。`EnvironmentMaintenance.recover()` 的分域执行器仍需分别调用实际回切，这是**执行分派**，不等于第二把写入权威。只有出现具体新域漏入 probe/执行器或错误回切证据时，才另立问题。
- 最终 Low 的 FD **281→279→279** 没有在这三次样本里持续上升；只说明该短时操作范围，不能推出所有 WebView/Gecko/guest FD 安全，也不能把未采到的 PSS/耗电算泄漏。保留清单 11 项正向检查/旋转通过，不代表正式用户历史达到 1,000 项。
- B01 的插件卸载旧版本、B02 的 v1 运行时原件、B04 的未知清单和 B05 的逐项最终报告都为救援/可访问性保留。C 组正在处理的 D06 英文应急语言不回填为 B 组数据缺陷。

**评分可行性边界。** B 组此前局部建议的数据事务 **1.75/5**、性能与可诊断性 **2.00/5**应由主报告结合上述队列再裁决：不能继续用“未在正式个人数据强杀”或“旧档未逐份验完”支撑高分。当前明确值得推进的是 DocumentsProvider 隔离复现；SMS/虚拟屏两项先定时序判据并做非敏感夹具。深页优化和插件归档范围取决于真实成本或产品选择，不是现有软件门禁失败。若这些有限验证均无法证明可避免问题，应下调相应局部债评价，而不是继续发明新需求或牺牲保护原则来接近 20。
